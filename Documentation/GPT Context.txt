CURRENT DESIGN MODEL:
The system uses named relationship contexts. Relationships are not treated as one global database-wide map by default. A relationship context represents a specific business or technical relationship area.

Examples:
- Property Ownership Relations
- Customer Relations
- Payment Relations
- Animal Registration Relations
- Regulatory Application Relations
- Module Relations

Each relationship context can store:
- Name
- Context type
- Purpose
- Business context
- Included tables
- Primary join path
- Conditional logic notes
- Query guidance
- Comments
- Owner/reviewer
- Status
- Created/updated timestamps

RELATIONSHIP MODEL:
Relationships are stored in a shared relationship registry and can be scoped to a context using context_id.

Relationship fields include:
- id
- context_id
- source_schema
- source_table
- source_column
- target_schema
- target_table
- target_column
- relationship_type
- cardinality
- join_type
- confidence
- condition_sql
- extra_join_sql
- description
- active

Supported relationship types:
- manual
- conditional
- inferred
- imported
- explicit_fk

Conditional relationships are NOT managed in a separate tab anymore.
They are created and edited as normal relationships with optional condition_sql.

Example:
source: PropertyWise.Associations_Role_Based.Item_Id
target: PropertyWise.Properties.Property_Id
condition_sql: src.Item_Type = 3
relationship_type: conditional

IMPORTANT CURRENT UI DECISION:
The separate Conditional Links tab was removed in v1.1.5.
Conditional links are now part of the main Relationships tab.

CURRENT ERD DECISION:
Mermaid visual rendering was attempted and reverted due to rendering/deprecation/syntax issues.
Mermaid is currently text/export only.
Graphviz exists as fallback.
The primary ERD visualisation is Streamlit Flow.

CURRENT ERD VISUALISATION:
The ERD View uses streamlit-flow-component to show table-style ERD nodes.

Current table-style ERD node layout:
Table_Name
schema · Rows: count

| Type | Column |
|---|---|
| PK | Primary_Id |
| KEY | Other_Id |
|     | Normal_Column |
| …   | X more columns |

Field markers:
PK = Primary key field
KEY = ID/key-like field
blank = normal field
… = hidden remaining columns

Key-like fields are detected using names ending in:
_Id
ID
_Key
Key
_Code
Code
_Number
Number
_No
No

ERD View supports:
- Whole database scope
- Active relationship context scope
- Dragging table nodes
- Pan/zoom
- Minimap
- Existing relationships as edges
- Conditional relationships shown as animated/labelled edges where supported
